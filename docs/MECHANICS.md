# Как «Дрёма» считает

Документ описывает все расчёты приложения: откуда берутся цифры на экранах, по каким формулам, и где у них пределы.
Каждая формула лежит в `src/engine/` отдельным файлом без обращений к браузеру, поэтому её можно прочитать и проверить тестами (`tests/`).

## Принципы

1. **Объяснимо.** Любое число на экране можно развернуть: экран «Почему так?» показывает те же слагаемые, что описаны ниже.
2. **Сначала возраст, потом ребёнок.** Пока записей мало, прогноз опирается на возрастной ориентир. Чем больше записей, тем больше вес истории ребёнка (но не больше 85 %).
3. **Устойчиво к выбросам.** Везде вместо среднего — медиана и квантили; одна затянувшаяся прогулка не сдвигает ритм.
4. **Честно про неточность.** Прогноз — это окно «±», а не одна минута. Точность прошлых прогнозов считается и показывается («8 из 10»).
5. **Данные у вас.** Всё хранится в браузере. Сервера нет — поэтому в конце документа перечислено, что без сервера невозможно.

## 1. Данные

Всё, что записывается, — событие: `id`, ребёнок, время начала `t`, время последнего изменения `updatedAt`, автор.
Типы: сон, кормление, подгузник, температура, лекарство, купание, прогулка, рост и вес, заметка (`src/engine/model.ts`).

- **Удаление — «надгробие»** (`deleted: true`), а не стирание. Так удаление можно отменить, а при будущем слиянии с другим устройством оно не «воскреснет».
- **Отмена** хранит 30 последних состояний. Фраза голосом, записавшая несколько событий, откатывается одним нажатием.
- **Проверка данных** (`src/store/state.ts`): при чтении из хранилища и из файла копии каждое поле проверяется по типу. Запись с неверным видом, нечисловым временем, «сном без конца» (кроме явного `null`) или с концом раньше начала отбрасывается. Две записи с одним `id` сливаются в более свежую. Поэтому повреждённый файл не может сломать экраны.

### Дневной и ночной сон

Вид сна определяется временем засыпания (`classifyStart`): **с 18:30 до 06:00 — ночной, иначе дневной**. Вид можно задать вручную в записи.
Ночь, разбитая на несколько кусков с перерывом меньше 4 часов, считается одной ночью.

### Где мы в сутках (`dayState`)

После последнего законченного сна определяется:

- `morning` — это было утреннее пробуждение (ночной сон, закончившийся между 04:30 и 12:00);
- `nap` — закончился дневной сон;
- `night-waking` — ночное пробуждение: прогноз не строится, пока не наступит утро.

Счётчик дневных снов обнуляется после утреннего пробуждения и после перерыва больше 10 часов.

## 2. Прогноз следующего сна

Файл `src/engine/predict.ts`, функция `computeForecast`. Выполняется после каждого пробуждения.

**Шаг 1. Что за окно.** Из возраста берётся строка таблицы (раздел 9). Если дневных снов уже было столько, сколько положено, следующий сон — ночной (`bedtime`), иначе дневной (`nap`). Номер окна — `снов было + 1`; окон в сутках `дневных снов по возрасту + 1`.

**Шаг 2. Возрастная оценка.** Середина диапазона окна бодрствования, умноженная на коэффициент места в дне:

| Окно | Коэффициент |
|---|---|
| первое (после утра) | 0,85 |
| последнее перед ночью | 1,15 |
| остальные | 1 |
| если в сутках ≤ 2 окон | 1 |

`prior = середина × коэффициент`, ограничено диапазоном `[мин × k × 0,9; макс × k × 1,1]`.

**Шаг 3. Личный ритм.** Берутся замеры «пробуждение → следующее засыпание» за 14 суток (`windowSamples`; промежутки короче 10 минут и длиннее 8 часов отбрасываются как ошибки записи).

- Если для *этого* окна есть **не меньше 3** замеров — берётся их медиана, разброс оценивается как `σ = 1,4826 × MAD`.
- Иначе, если во всех дневных окнах **не меньше 5** замеров, они приводятся к текущему окну делением на их коэффициенты и умножением на текущий; вес таких замеров вдвое меньше (`n_эфф = n / 2`).
- Иначе личного ритма нет, прогноз целиком по возрасту.

Выбросы отбрасываются (`dropOutliers`): значения дальше **трёх σ** от медианы, если замеров не меньше 6. Если больше половины значений совпали с медианой (MAD = 0), минимальный разброс берётся равным 5 % медианы.

**Шаг 4. Смесь.**

```
вес      w = min(0,85; n / (n + 4))
смесь      = (1 − w) × возрастная + w × личная
```

Четыре — «сила» возрастной нормы: она весит как четыре замера. При 14 замерах `w = 14/18 ≈ 0,78`.

**Шаг 5. Поправка на длину прошлого сна** (только после дневного сна). Сравнивается длина только что закончившегося сна с обычной (медиана за 14 суток при ≥ 5 снов, иначе середина возрастного диапазона):

```
adj = clamp( (прошлый − обычный) / обычный × 0,15 ; −0,15 ; +0,05 )
```

Короткий сон приближает следующий (до −15 %), длинный отодвигает чуть-чуть (до +5 %): асимметрия намеренная — недосып сильнее влияет на окно, чем «пересып».
Итог ограничен диапазоном `[мин × k × 0,75; макс × k × 1,25]`.

**Шаг 6. Время.** `прогноз = пробуждение + итог`, округлённый до 5 минут по местному времени.

**Шаг 7. Ночной сон.** Прогноз отбоя зажимается вокруг целевого времени: не раньше целевого − 60 минут и не позже целевого + 45, но и не раньше, чем через `0,6 × минимальное окно` после пробуждения. Целевое время: желаемое из настроек → медиана отбоев за 7 суток (если их ≥ 3 и они между 17:30 и 23:30) → возрастная норма.

**Шаг 8. Ширина окна.** Полуширина: `w × σ + (1 − w) × возрастная_полуширина`, округляется до 5 минут и ограничивается от 10 до 25 минут. Возрастная полуширина — полразмаха диапазона окна, тоже в пределах 10–25.

### Пример (экран «Сегодня», 13:42)

Мила, 5 месяцев, проснулась в 12:10 после второго дневного сна. Это третье окно из пяти.

| Слагаемое | Значение |
|---|---|
| диапазон по возрасту | 120–150 мин → середина 135, коэффициент 1 |
| личный ритм | 14 замеров, медиана 131 мин, σ ≈ 11,9 |
| вес личного ритма | 14 / (14 + 4) = 0,78 |
| смесь | 0,22 × 135 + 0,78 × 131 = 131,9 мин |
| поправка | прошлый сон 70 мин при обычных 73 → −0,6 % ≈ −0,8 мин |
| прогноз | 12:10 + 131,1 мин = 14:21 → **14:20** |
| полуширина | 0,78 × 11,9 + 0,22 × 15 = 12,6 → до 5 минут → **15** |

Окно 14:05–14:35. Эти же числа проверяются тестом `tests/golden.test.ts`.

## 3. Сколько продлится сон

`computeOutlook`. Для дневного сна — «обычный диапазон» из квартилей (25 %–75 %) длин дневных снов за 14 суток, если их ≥ 5 (после отсечения выбросов); иначе — возрастной диапазон. Если квартили почти совпали (разница < 10 минут), диапазон расширяется на 5 минут в обе стороны. Шкала кольца — верхняя граница + 30 минут, вверх до 30.
Для ночного сна диапазона нет, считается суммарная ночь (цепочка кусков).

## 4. Точность прогноза («8 из 10»)

`backtest`. Для каждого из последних десяти засыпаний за 7 суток прогноз **пересчитывается заново так, как если бы мы знали только то, что было известно в момент пробуждения** (будущие записи отрезаются). Попаданием считается засыпание внутри окна `[начало; конец]`. Это честная проверка на прошлом, а не подгонка: цифры на экране «Почему так?» не вводятся вручную.

## 5. Кормление

- **Обычный промежуток** (`typicalFeedInterval`): медиана промежутков между кормлениями за 7 суток, если их не меньше 8; промежутки короче 30 минут (докорм) и длиннее 8 часов (пропущенная запись) не считаются; результат округляется до 5 минут и ограничивается 1–6 часами. Иначе — возрастная норма.
- **Кольцо «с последнего кормления»**: `прошло / обычный промежуток`, не больше полного круга.
- Кормление записывается тремя способами: бутылочка (мл), грудь (минуты по сторонам или общее время), прикорм (что дали).

## 6. Неделя, месяц и выписка

`src/engine/week.ts`, `src/engine/report.ts`.

- **Сутки** режутся по местной полуночи; сон через полночь делится между сутками, идущий сон считается до «сейчас».
- **Средние** считаются по *законченным* суткам, в которых есть хоть одна запись. Пустые дни не занижают среднее. В первый день использования берётся то, что есть.
- **Столбики** отчёта: шкала 0–16,5 ч на 110 px (верх нормы 16 ч плюс запас).
- **Выписка для педиатра**: сон (среднее, минимум и максимум, ночь/день), питание (с округлением смеси до 10 мл), подгузники, температура (максимум и последние шесть измерений), лекарства (последние восемь), последние рост и вес, ваш вопрос врачу. Если записей нет, так и написано — цифры не выдумываются. Внизу приписка, что это не медицинское заключение.
- Температура от **37,5 °C** считается повышенной (число таких дней — `feverDays`). Это справочная отметка в выписке, а не диагноз.

## 7. Ночной режим

Включается сам, когда время попадает в «ночь» из настроек (по умолчанию 21:00–06:00) и вы не вышли из него вручную. Если вы вышли — экран не вернётся до следующей ночи. Автооткрытый ночной экран закрывается сам утром; открытый вручную — нет. В тёмной теме шторки тоже тёмные.

## 8. Напоминания

`src/engine/reminders.ts` (что напомнить) и `src/app/reminders.ts` (как показать).

| Напоминание | Когда | Живёт до |
|---|---|---|
| Скоро окно сна | за N минут (по умолчанию 10) до начала окна | конца окна |
| Пора кормить? | через обычный промежуток после последнего кормления | +45 минут |
| Пора будить | через верх обычной длины дневного сна + 15 минут запаса | +2 часа |

Каждое напоминание имеет идентификатор, привязанный к событию (`window:<пробуждение>`, `feed:<кормление>`, `wake:<засыпание>`), поэтому одно и то же не прозвучит дважды, а новое пробуждение даёт новое напоминание. Показанные идентификаторы запоминаются в браузере.

> **Ограничение.** Без сервера браузер не запускает код, когда приложение закрыто. Напоминание сработает, пока приложение открыто или свёрнуто. Чтобы уведомления приходили при закрытом приложении, нужен сервер с push-уведомлениями.

## 9. Возрастные ориентиры

Это **не медицинские нормы**, а стартовая точка для прогноза. Как только накоплена история ребёнка, прогноз опирается на неё.

| Возраст (полных мес.) | Окно бодрствования, мин | Дневных снов | Длина дневного сна, мин | Сон за сутки, ч | Отбой | Кормление раз в, мин |
|---|---|---|---|---|---|---|
| 0 | 30–60 | 5 | 30–120 | 14–17 | 21:30 | 150 |
| 1 | 45–75 | 5 | 30–120 | 14–17 | 21:30 | 150 |
| 2 | 60–90 | 4 | 30–120 | 14–17 | 21:30 | 180 |
| 3 | 90–120 | 4 | 30–105 | 14–17 | 21:00 | 180 |
| 4 | 105–135 | 4 | 30–90 | 12–16 | 21:00 | 180 |
| 5 | 120–150 | 4 | 45–90 | 12–16 | 20:00 | 180 |
| 6 | 135–165 | 3 | 45–90 | 12–16 | 20:00 | 210 |
| 7 | 150–180 | 3 | 45–90 | 12–16 | 20:00 | 210 |
| 8 | 165–195 | 3 | 45–105 | 12–16 | 20:00 | 210 |
| 9 | 165–210 | 2 | 60–105 | 12–16 | 20:00 | 240 |
| 10 | 180–225 | 2 | 60–120 | 12–16 | 19:45 | 240 |
| 11 | 180–240 | 2 | 60–120 | 12–16 | 19:45 | 240 |
| 12–14 | 180–240 | 2 | 60–120 | 11–14 | 19:45 | 270 |
| 15–17 | 240–300 | 1 | 60–150 | 11–14 | 19:45 | 270 |

| 24+ | 300–360 | 1 | 60–120 | 11–14 | 20:00 | 270 |

Откуда цифры:

- **Сон за сутки** — консенсус Американской академии медицины сна (AASM, 2016): 4–12 месяцев — 12–16 часов, 1–2 года — 11–14 часов. До 4 месяцев — ориентир 14–17 часов (National Sleep Foundation, 2015).
- **Окна бодрствования, число и длина дневных снов, время отбоя** — единого научного стандарта нет. Популярные источники (клиники и сервисы про детский сон) заметно расходятся друг с другом, поэтому в таблице взяты осторожные средние значения. Не воспринимайте их как норму для вашего ребёнка: именно поэтому приложение так быстро переходит на личные записи.
- **Кормление раз в** — ориентир для «кольца» и напоминания, пока своей истории нет. Не рекомендация по режиму кормления.

## 10. Голосовой ввод

`src/engine/voice.ts`. Распознаёт речь сам браузер (Web Speech API; где его нет, фразу можно набрать). Приложение разбирает **текст**:

1. Нормализация: нижний регистр, «ё» → «е», числа словами → цифры («сто двадцать» → 120, «тридцать шесть и шесть» → 36.6).
2. Фраза делится на части по запятым и словам «и», «а», «потом», «затем», «ещё». Кусок без глагола присоединяется к предыдущему действию только если это дополнение к нему (число, сторона груди, единица измерения, продукт); иначе он попадает в «не поняла».
3. Для каждой части определяется намерение по ключевым словам и берётся время: «только что», «полчаса назад», «20 минут назад», «в 14:20», «в 7 утра», «в 2 часа дня», «вчера в 23:00».
4. Время в будущем невозможно: «в 14:50», сказанное в 14:20, — это вчерашнее 14:50; если час не уточнён («в 9:30»), берётся ближайшее прошедшее из вариантов (9:30 или 21:30).
5. Перед записью приложение показывает, что поняло, и ждёт подтверждения. Непонятая часть показывается отдельно, ничего не записывается молча.
6. «Пописал и покакал» — один подгузник «мокрый и грязный», а не два.

Разбор проверяют ~110 тестов, в том числе регрессия на кириллицу (в JavaScript `\b` и `\w` не видят русских букв, поэтому границы слов собираются через Unicode).

## 11. Совместный доступ

Сервера нет, поэтому живой синхронизации между телефонами **нет**. Что есть:

- **Ссылка «только смотреть»**: в адресе закодирован снимок (имя, пол, когда уснула или проснулась, когда кормили, прогноз, обычная длительность сна). Открывший ссылку видит живой таймер от этих отметок. Через 6 часов снимок помечается устаревшим — нужна новая ссылка. Ссылка не содержит журнала: только эти отметки.
- **Резервная копия** — файл JSON: сохранить, перенести на другое устройство, загрузить. Загрузка заменяет данные целиком и проходит ту же проверку, что и чтение из хранилища.

Для живой синхронизации и ролей «редактирует / смотрит» нужен сервер: модель данных к этому готова (отметки изменения и «надгробия» нужны для слияния), но сам сервер в этот репозиторий не входит.

## 12. Чего приложение не делает

- Не ставит диагнозов и не даёт медицинских рекомендаций. Температура, лекарства, рост и вес — записи для выписки врачу.
- Не отправляет данные никуда само: нет аналитики, нет запросов на сервер. Исходящие действия — только те, что вы запускаете сами (поделиться выпиской, ссылкой).
- Не синхронизирует устройства вживую и не присылает уведомления при закрытом приложении (раздел 8, 11).
- Распознавание речи зависит от браузера и может отправлять звук на сервер распознавания браузера (это делает сам браузер, не приложение).

## 13. Как это проверено

| Проверка | Команда | Что подтверждает |
|---|---|---|
| Типы | `npm run typecheck` | строгий TypeScript без неиспользуемого |
| Модульные тесты | `npm test` | формулы, голосовой разбор, хранилище, отмена, проверка данных, напоминания, ссылки, выписка |
| «Золотые» числа | входит в `npm test` | на демо-данных движок выдаёт ровно цифры макета: 14:20 ±15, «8 из 10», 14 замеров, вес 0,78 и т. д. |
| Пиксельная сверка | `npm run test:visual` | 8 экранов совпадают с макетом V3 (допуск 0,1 %, фактически 0–0,015 %) |
| Сценарии в браузере | `npm run test:e2e` | 24 сценария в настоящем Chromium: сон, кормление, голос, дети, ночь, выписка, копия, доступность |
| Офлайн | `npm run test:offline` | service worker ставится и приложение открывается без сети |
